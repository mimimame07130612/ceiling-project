最初に読むこと

更新日時：2026年9月5日 18:17

① この文書の目的を以下に示す
1-1. セッションを跨いで検討の進め方・結果の継続性を担保するための情報伝達ルール
1-2. プロジェクト内でのClaudeの行動指針・基本的ルール

②プロジェクトの概要
2-1. プロジェクトの概要を把握するため、まず【プロジェクト概要.txt】を全文読み取ること。

③ ファイル名における注意事項
3-1.このプロジェクトで作成する各文書・成果物のファイル名にはすべてプレフィクス（タイムスタンプ）が付加し、このタイムスタンプで版管理を行う。
3-2.プレフィクスの書式は「 YYMMDDhhmm_ 」とする。文書作成時に『TZ=Asia/Tokyo date +%y%m%d%H%M』 で取得する。推測で記載しない。 文書内に記載する作成日時も同じ値を用いる。
3-3.フォルダ内に同文書が複数保管されている場合は、プレフィクスの最も大きなものを最新版として取り扱う。
3-4.この文書内および各ルール文書内ではファイル名からプレフィクスを省略して記載している。

④文書体系
4-1. このプロジェクトのファイルを保管するフォルダを以下に示す。
　　a) DropBox/Claude/真CINEMAドライブ/　（以下、DB）
　　b) ナレッジベース　（以下、KB）
　　c) GitHubリポジトリ　https://github.com/mimimame07130612/ceiling-project.git　（以下、GH）
4-2. プロジェクトで扱う文書一覧が【KB/文書体系.csv】に記載されている。これを読み取り、内容を理解すること。
4-3. 各文書に記載する項目にはID（番号）を付与し、それぞれの参照関係をあとからでも追跡できるようにすること。ID取得のルールは【KB/文書体系.csv】に併記している。
4-4. DBに保管する版を原本とする。KB・GH・チャットに置くものは原本の複製であり、配布物という。文書ごとの原本と配布先は【KB/文書体系.csv】による。
4-5. Claudeが読み取るのは配布物とする。配布先の定義が無い文書は原本を読み取る。

⑤基本ルール
5-1. セッション開始、最初のレスポンスの冒頭に「第XX回セッション、YYMMDDhhmm 開始」とチャット上に出力する。（XXは実際のセッション回数、YYMMDDhhmmは『TZ=Asia/Tokyo date +%y%m%d%H%M』 で取得する）
5-2. セッション開始時、【引き継ぎファイル.md】のアップロードがあった場合は内容を読み取り、当該セッションで取り組む項目を宣言する。
※【引き継ぎファイル.md】に記載されている当該セッションで取り組む項目が10件以上ある場合は、最初の10件の内容と全項目数の宣言とする。
5-3. セッション進行中、次のいずれかの時点で、『セッション開始からその時点のターン数（依頼主の発言を1と数える）』と『滞留量の総合計』を申告すること。
　(a) 5-2で宣言した取り組み内容が1件、完了へ遷移したとき
　(b) セッション内で依頼主が指示した作業が1件、完了へ遷移したとき
　(c) 依頼主が当該セッションの区切りまたはまとめを示唆したとき
　※ 滞留量の総合計 は以下で計算する。
　　（滞留量）×（発生した時点から申告するターンまでの経過ターン数）の総和
　　　　　経過ターン数は、発生したターンを1として数える。（依頼主の発言を1と数える）
　　　　　滞留量で計上するのは、画面出力として文脈に載った分のみとする。 curlで /tmp へ落としただけで表示していない分は計上しない。
　　　　・ローカル／添付／ナレッジベース：表示された範囲の実測バイト数
　　　　・Dropbox：fetchで取得したファイルのバイト数
　　　　・GitHub：awkで抽出して表示した範囲の実測バイト数
　　　　・PDF：抽出されたテキストのバイト数（ファイルのバイト数ではない）
　　　　・ファイル出力：出力したファイルのバイト数
　　　　・svgその他のテキスト形式のファイルは、他のテキストと同様に計上する。
　　　　・web調査：表示された範囲の実測バイト数
　　　　・bashのコマンド文：発行したコマンド文字列のバイト数
　　　　・ラスタ画像（jpeg・png等）は計上しない。
　　　　・Claudeの返信は計上しない。
　※ 『セッション開始からその時点のターン数』と『滞留量の総合計』はpythonで算出すること。台帳は、セッション内で最初にbashを実行する時点で作成する。算出スクリプトは【ツールリスト】のT001をGHから取得し、内容を表示せずに実行する。2回目以降の申告はそのスクリプトを実行する。
　※ 進行中の申告は上記2値のみとする。ターン別の一覧は作成しない。ターン別一覧はまとめ作業時に bash_log.tsv から再構成する。
　※ 5-3.は、取り組み項目が1件完了となるたびに繰り返し申告すること。
　※ 本項の目的は、文脈に載り続けている情報量を可視化し、セッションを打ち切る判断の材料を依頼主へ渡すことにある。数値そのものの最小化を目的としない。
5-4. 成果物・文書（画像・MDファイル等）を出力する際には【出力ルール】にしたがって実施すること。セッション内で初めて出力する前に【出力ルール】を読み取る。2回目以降の出力する際はルールの読み取りは行わずに出力を実施する。
5-5. 依頼主から「まとめて」等で当該セッションのまとめを指示されたときは、【まとめルール】を読み取り、そこに記載されている内容にしたがってまとめ作業を実施する。
5-6. 依頼主からルールの改訂を指示されたときは、【ルール改訂ルール】を読み取り、そこに記載されている内容にしたがってルール改訂作業を実施する。
5-7. 確定事項ファイル・未確定事項ファイルへ起票または改訂をするときは、事前に依頼主へ申告し承認を得る。着手前に当該ファイルの1節および2節を取得する。
5-8. 文書を開く前に、表示する範囲のバイト数を取得する。この値が生存量以下であれば、承認を求めずに開いてよい。生存量を上回るときは事前に依頼主へ申告し、承認を得る。
　※ 生存量は、bash_log.tsv に計上された出力バイト数とコマンド文バイト数の総和とする。経過ターン数を乗じない。5-3のスクリプトから出力する。
　※ 承認なく開ける量は、1ターンあたり合計で生存量を上限とする。
　※ 承認なく開いたときは、当該ターンの返信に文書名と実測バイト数を記す。
　※ まとめファイルは、バイト数にかかわらず、開く前に【まとめ履歴】を検索して対象を特定し、まとめファイルIDと節を宣言する。
　※ 事前にバイト数を取得できない経路は本項の対象外とする。
5-9. 5-2の実行に続けて、【引き継ぎファイル】3節(a)に記載された文書について未配置チェック（【まとめルール】3）を実行し、結果を宣言する。

⑥Claude行動指針
6-1. Claudeは事実に基づかない勝手な判断で論理を構築しない。
6-2. まだ開いていない文書について、その内容・構造・問題点を述べない。開く／依頼主に聞く／判らないと述べる、の3択とする。
6-3. 規程どおりに実行しない判断をしたときは、実行前に「どの条項を／どう読み替えて／なぜ外れるか」を申告し、依頼主の承認を得る。
6-4. 検討案件の成否を結論づける際には、制約が譲歩の余地のない固定なものか交渉可能なものかを監査する。
6-5. 口頭の見立てを先に述べず、作図・計算を先行させること。さらに 「まず絵で見る」を基本の進め方とする。
6-6. 承認済みの数値・算出結果を後続の検討の入力に用いるときは、当該ターンで再算出した値を併記する。両者が一致しないときは、検討を進めず依頼主へ申告する。
6-7. 算出結果を提示するときは、その結果が成立する前提を併記する。前提には、値が変われば結果が変わる入力と、結果の適用範囲を画する条件を含める。前提を書けない算出結果は提示しない。


［具体的な行動］
以下の内容を遵守すること
※記憶（userMemories）の記載を行動の根拠にする場合、対応する文書またはカスタム指示をセッション中に既に読んでいれば、記憶ではなくその記載に従う。
※bashの出力はClaudeが読むためのものであり、整形は返信側で行う。
   見出し・ラベル・区切り線を付けず、値のみを出す。
   ただし自分が読み違えない最小限の区切りは保つ。
※bashの日本語の文字数はpythonで数える。awkのlengthはバイト数を返し、結果が約3倍ずれる。
※bashの叩き直しは出力2回分とコマンド文2回分を消費し、その両方が以降の全メッセージに乗算で加算される。1回で当てる。
※bashで外部へ書き込む内容は、必ず直前にローカルから読み込んでから渡す。スクリプトで生成したファイルも同じ。生成しただけでは内容はClaudeの手元になく、読み込まなければ送られるのは記憶の再構成物になる。この読み込みは省略できない。
※bashを叩くときは、コマンド全体を { } で囲み、標準エラー出力をファイルへ逃がす。末尾3行のみを出力する（　2>/dev/null だと失敗の原因が見えなくなる　）
　書式：{ コマンド ; } 2>/tmp/e; tail -3 /tmp/e
※web上のpdfはサイズが不明のためclaudeは読み込まない。依頼主にurlを共有し依頼主がダウンロードしたのちチャットにアップロードする運用とする。
※GitHub上の文書を読むときは raw.githubusercontent.com のURLを用いる。
※GitHub上の文書を読むときは、curlで /tmp へ落としたうえで、awkで必要な節のみを抽出して表示する。全文を表示しない。
　書式：{ curl -s -o /tmp/f.txt <URL> ; awk '/^5 /{f=1} /^6 /{f=0} f' /tmp/f.txt ; } 2>/tmp/e; tail -3 /tmp/e
　節の書式は「行頭に節番号＋半角スペース」とする。csvの場合は「行頭に節番号＋カンマ」とする。
　csvから列の値で行を抽出する場合の書式：
　{ curl -s -o /tmp/f.csv <URL> ; awk -F, -v k=<値> '$N==k' /tmp/f.csv ; } 2>/tmp/e; tail -3 /tmp/e
　$N の列番号は対象ファイルの構造に従う。
※bashを実行するつど、ターン番号・コマンド・終了コード・出力バイト数・コマンド文バイト数の5列を /home/claude/bash_log.tsv へ追記する。ヘッダ行を置かない。bash以外で計上が発生したときも同じ5列で追記し、コマンド列には発生元を記す。滞留量の台帳はこのファイル1本とし、別に台帳を作らない。5-3の申告値はこのファイルのみを入力とするスクリプトの出力をそのまま用い、手で値を加算しない。追記はコマンド本体と同じ { } の中で行い、別呼び出しにしない。集計はまとめ作業の冒頭で行う。
